# Telegram 指令、变化量提醒与批量设置

## 目标

在不改变现有金额跨档提醒的前提下，提升临时查询、突发波动发现和多代理维护效率。

## 已选方案

### Telegram 指令

- 保留 `/report`、`/status` 及中文别名。
- 新增 `/top`、`/alerts`、`/check [账号名]`、`/help`。
- `/top` 与 `/check` 先刷新在线电脑上的启用账号，再返回当前周数据；`/check` 带账号名时按显示名称精确匹配，找不到时明确回复。
- `/alerts` 返回本机最近 10 条金额提醒结果；`/help` 由 Worker 直接回复一次，不依赖桌面端在线。
- Worker 继续只接受唯一机器人拥有者的私聊。命令以结构化 JSON 存在既有 `commands.command` 文本列中，无需扩展 D1 架构。

### 单次变化量提醒

- 每个代理增加可选 `deltaAlertStep`，表示“本次成功读取相对上一次成功读取”的绝对变化阈值。
- 未设置即关闭；过期数据、首次成功读取和静默时间内不发送。
- 读取成功后将当前值作为下一次比较基线；若实际发送失败，不推进该代理基线，以便下次重试。
- 变化量提醒与金额跨档提醒独立，并写入既有提醒记录页，标记为“变化量提醒”。

### 批量设置

- 每个账号表格单独选择代理，避免跨盘口误改。
- 批量表单的空金额字段表示“不改”；备注通过“同步备注”开关明确是否修改，支持清空；另有清除金额跨档提醒和清除变化量提醒选项。
- 批量操作更新持久配置、当前运行时状态，并请求该账号重新读取。

## 取舍

- 不做跨账号一键批量：不同账号的口径和金额尺度可能不同。
- 不把 `/help` 排入桌面命令队列：离线时仍可立即获得帮助，且不会由多台电脑重复回复。
- 变化量按“相邻两次成功读取”计算，不按固定 10 分钟累计，因每个账号原本就有不同的检查间隔。

## 验证

- Worker 测试覆盖所有命令、所有者限制和带参数的 `/check`。
- Monitor 测试覆盖首次读取、阈值、静默、失败重试和提醒记录。
- UI 冒烟覆盖单项变化量输入、选中代理和批量提交。
- 部署前运行 Node、Electron 桌面与 Windows 验证构建；Worker 使用 `wrangler check`、测试、干运行与正式部署；随后发布桌面更新并核对 R2 清单。
