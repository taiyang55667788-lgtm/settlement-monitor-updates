长期维护和交接信息见 [MAINTENANCE_CONTEXT.md](MAINTENANCE_CONTEXT.md)。

跨平台桌面应用，支持 166 与皇冠两套账号系统；按系统登录并读取对应的本周交收结果，再按固定金额间隔发送 Telegram 通知。界面提供本周最近提醒档位、最后成功读取时间及四种主题。

v1.0.28 已发布：未达首档不再清除上次非零提醒档位。每 30 万一档时，30→20→30 万只提醒首次；30→60→30 万提醒三次，负数对称，换周重新计数。已有零档记录按明确历史恢复；无顺序证据的双向旧记录不猜测。界面显示“未达首档，保留档位记录”。Telegram 金额档位通知将备注放在代理账号后括号内，移除报表区间和当前档位，显示“上一次档位”；首次显示“无（首次提醒）”。内部周期、档位与备注记录保持完整。

v1.0.27 已发布：金额通知入队、元数据与档位推进一次保存；零档也遵守连续确认，金额在同档内波动不重复提醒，正负跨档与回落仍提醒。通知保留编号和档位变化轨迹，界面可查看待发消息、重试或确认取消。已收到成功回执但本机写盘失败时，同一进程只补写记录，不再次发送。

全量扫描保留六小时断点，首两级与重点路径仍刷新；确认末级缓存六小时，手动全量扫描清空缓存。长全量扫描按检查间隔串行插入重点读取。单行提醒设置热更新不取消整轮，后续检查合并安排；自动账号检查错峰，连续失败退避。界面区分等待、按需更新和读取失败，并显示重点数据年龄。配置写盘失败回滚内存，保留加密备份，非关键事件/结构断点合并保存；从损坏配置恢复备份后，需核对并确认恢复监控。软件更新页显示启动/升级后的首次读取自检，异常也在顶部提示。

121 项 Node 测试、三项桌面流程和 Windows 构建验证均通过。不承诺真实盘口加速比例。Telegram 已接收但回执丢失、进程崩溃，以及两台电脑同时监控同账号，仍存在重复的边界；目前没有跨设备去重。请结合通知编号、档位轨迹与诊断包定位，不把“每周同档只发一次”作为去重策略。

v1.0.25 稳定性优化（已发布）：优先读取已设置提醒的分支，失败分支放到其他分支之后补读一次；复用有效查询表单，校验本轮表格已更新，本周查询最多等待 30 秒。Telegram 通知进入本机加密队列，不再阻塞下钻，断网退避重试并标记原始时间；提醒记录只记录真实发送尝试，待发与已发送分别显示。重点代理超过三个检查间隔（至少五分钟）未更新会预警。部分失败、需要手动处理、恢复中和数据过期分开展示；休眠中断旧读取，唤醒或检测到网络恢复后安排重新检查。单次读取操作超过 150 秒会关闭旧页面并恢复调度。

通知队列最多保留 2000 条，满时明确报错，不静默覆盖。更换 Telegram 收件人后旧队列暂存，不转发给新收件人。Telegram 无事务性送达确认，网络中断恰好发生在服务端接收后时，补发仍有重复的可能。电脑休眠/关机期间不能读取；Windows 实际盘口速度与长期稳定性仍需实机验证。

## 功能

- v1.0.28 已发布补充：金额间隔发生变化时，清除该代理新间隔的旧判断档位，重新读取后按新间隔提醒（继续遵守连续确认与静默策略）；保存相同间隔或仅改备注不重置。提醒记录新增可展开的触发详情，包含原因、前后档位、上次档位转换金额、本次金额、进程启动及间隔修改记录；诊断包同步包含这些记录。旧消息队列与实际发送历史不清除，无每日摘要。

- v1.0.26 修复（已发布）：新建空白窗口先加载网站，不再先执行登录探测脚本；已有页面会话检查设 5 秒超时，超时后关闭旧页面、保留会话分区并重建加载，只重试一次。详情区区分初始化窗口、会话检查、打开登录页和重建阶段，每轮清空旧查询耗时。

- 多个本级账号并行监控，各自使用独立浏览器会话
- v1.0.23：保留有效登录窗口，四级代理沿当前路径继续下钻；每批有效数据及时显示并判断提醒。显示读取进度、上轮耗时及故障类别，诊断包包含各分支耗时。检查间隔从本轮开始计算，同账号不会重叠读取。
- 166 固定使用 `166.tt`，需要安全码、账号和密码；自动选择延迟最低的代理线路
- 皇冠只允许 `ag.hga050.com`、`ag.hga030.com`、`ag.mos011.com` 三个固定站点；账号如已设定安全码会一并填写，未设定可留空
- 皇冠登入一、二、三只决定登录入口；进入后统一读取本周“观看总代理”中的每个总代理账号
- 分段式盘口登录配置界面，安全码在输入及重新编辑时都直接显示；密码仍不回显
- 数字验证码在本机经多种图像预处理后交叉识别；仅在结果一致或置信度足够高时自动提交，低置信度会换图而不盲目提交
- 皇冠检测到图形验证时会暂停自动提交、自动打开“盘内查看”并预填账号、密码和安全码；用户完成验证后会话继续用于自动监控
- 兼容导航站随机域名跳转，不会把正常跳转误判为登录失败
- 显示代理线路测速结果、当前登录阶段和明确的失败位置
- 自动检测掉线并重新登录

- 每次读取都核对“本星期”日期范围与报表顶部显示的周期和代理层级；核对失败即停止，避免把“今天”数据当作本周数据

- 账户显示最近成功读取、连续失败次数和下次检查时间；连续失败达到可设置次数时会升级通知 Telegram
- 自动保留最近 7 天成功读取趋势，并在每个代理金额下显示简要走势与变化量
- 提醒策略支持连续读取确认、连续失败升级和可选静默时间；默认静默关闭，全天即时通知，静默期间的新档位会在结束后下次成功读取时补发
- 可导出不含账号密码、安全码和 Telegram 凭据的诊断包；可导出与恢复仅限同一系统账户使用的加密配置备份
- 不同监控口径的提醒记录自动隔离；切换口径后的首次读取只发送一条已跨档位汇总
- 深蓝、石墨黑、浅色、高对比四种主题；应用金额正数蓝色、负数红色，Telegram 用蓝红圆点标识正负
- Telegram 官方机器人支持多人分别用一次性配对码绑定自己的私聊；群管理员也可把设备绑定到群通知。原 Bot Token + Chat ID 手动方式保留在高级设置
- 盘口结算周按周一早上 6:00 切换；日期或层级校验异常会自动重读 3 次，首次读取失败与恢复正常均会 Telegram 通知

- 已配对的 Telegram 私聊或群聊还支持 `/top`、`/alerts`、`/check [账号名]` 和 `/help`；每个代理独立设置金额档位和单次变化量提醒。
- v1.0.23：取消批量设置；代理默认显示第一级，逐级展开，支持“只看已设置提醒”（保留上级路径）。首次完整扫描最多四级，后续读取前两级及第三级以后设有金额或变化提醒的分支。“全量扫描”可发现新增深层代理。未查询代理保留上次金额并标记“本轮未刷新”，不参与提醒；保存提醒后自动安排重新读取。

## 开发运行

需要 Node.js 22 或更高版本（测试使用内置 SQLite），以及 pnpm。

```bash
pnpm install
pnpm start
```

发布前先运行 `pnpm test` 和 `pnpm test:desktop`。后者会在隔离的模拟报表中验证后台页面四级下钻、同名代理的路径隔离、层级表格编辑，以及旧设置迁移；真实盘口登录和报表结构仍需在可访问的网站上核对。

## 打包

```bash
npm run build:win
npm run build:mac
npm run build:linux
```

Windows 安装包需要在 Windows 电脑上执行 `npm run build:win`；macOS 安装包需要在 Mac 上构建。生成文件位于 `dist`。

## 自动更新发布

Windows 版本默认从 Cloudflare R2 检查更新。推送 `v*` 标签后，GitHub Actions 会先运行测试，再构建安装包、便携版、`latest.yml` 和差分更新文件并发布。也可先手动运行工作流，仅生成供检查的 Windows 安装包，不推送更新。应用会自动比较版本号、下载更新，并在用户确认重启后安装。

发布新版本前先修改 `package.json` 的 `version`。正式分发 macOS 版本时需要使用 Apple Developer 证书签名；Windows 建议使用代码签名证书，避免系统安全警告。

## Telegram 配对

配对服务的部署说明见 [pairing-service/README.md](pairing-service/README.md)。Worker 地址已配置在 `electron/pairing-config.js`。每台电脑在应用中点击“生成配对码”后，可由任意用户私聊官方机器人并发送该码；多人之间的设备和消息按各自 Telegram 私聊隔离。群通知则需要把机器人加入群并设为管理员，再由群管理员发送 `/pair 配对码`。Bot Token 仅保存在 Cloudflare Worker Secret，不会进入安装包或桌面应用的本地设置；盘口账号、安全码和密码仍只保存在电脑本机。

官方机器人配对模式由 Cloudflare Worker 调用 Telegram 官方接口，运行监控的电脑不直接访问 Telegram API；只要电脑可访问配对服务，日常通知无需为 Telegram 单独设置代理。旧的手动 Bot Token 模式仍由本机直连 Telegram，网络受限时可能需要系统代理。

如果配对服务不可用，仍可使用“高级设置”中的原手动方式：

1. 在 Telegram 联系 `@BotFather` 创建机器人并取得 Bot Token。
2. 先给机器人发一条消息。
3. 把 Token 填入应用，点击“自动获取 Chat ID”，保存后发送测试消息。
