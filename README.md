# 交收监控

Electron 桌面监控应用：独立登录多个盘口账号，读取本周交收报表，按代理设置发送 Telegram 提醒。只读报表，不下注、不修改盘口数据。

当前正式版：**v1.0.42**（2026-10-17）。本文只描述当前规则；旧版本记录见 [历史归档](docs/history/README-2026-10-16.md)。维护、验证及发布证据见 [MAINTENANCE_CONTEXT.md](MAINTENANCE_CONTEXT.md)。

## 安装与开始使用

1. 下载 [Windows 安装包 v1.0.42](https://pub-649c460a80df4ab1a6c668e4e67e2b6d.r2.dev/Settlement-Monitor-Setup-1.0.42-x64.exe)，安装并打开。
2. 添加盘口账号，填写对应登录资料，核对首次读取结果；需要人工验证时通过“盘内查看”完成。
3. 在 Telegram 页生成配对码，发送给官方机器人完成配对，再发送测试消息。
4. 给需要监控的代理设置金额档位、可选变化阈值和备注，保存后检查读取状态。

应用启动时及每 6 小时检查更新，后台下载后提示重启安装；“软件更新”页提供固定最新版下载入口。使用 Windows 安装版升级可保留本机加密设置。电脑必须保持开机、程序运行和网络可用；休眠或关机时不能监控。

## 账号与报表口径

| 系统 | 登录与读取范围 | 提醒依据 |
| --- | --- | --- |
| 166 | `166.tt`，安全码必填；最多四级下级代理 | 本周应收下线 |
| 皇冠 | `ag.hga050.com`、`ag.hga030.com`、`ag.mos011.com`；安全码按账号填写；登入一/二/三仅决定入口 | 每个总代理的本周“总代理结果” |

皇冠“总代理实货量”仅供查看，不参与金额提醒和趋势。每个本级账号使用独立会话。查询必须核对周区间、代理路径及唯一目标金额列；表头缺失、错位、重复或会话失效不能当作零金额使用。

## 读取与运行规则

- 首次完整扫描最多四级；日常读取前两级及深层设置了金额/变化提醒的路径。新增深层代理可通过“全量扫描”发现。
- 代理默认折叠，逐级展开；支持只看设置提醒的代理并保留上级路径。没有批量设置功能。
- 166 直接读取优先：网页学习并核对真实查询后，在同账号登录会话内复用；模板过期或校验失败回退网页。皇冠使用其专属报表流程。
- 同账号读取串行、不重叠；健康分支正常更新，失败分支独立退避并到期补读。补读不会把缓存数据伪装成新读取，也不推迟正常整轮计划。
- 每天本机时间 06:00—07:00 停盘，07:00:30 恢复；部署电脑应使用北京时间。周一 07:00 切周，只有校验到有效新周报表后才推进新周提醒状态；未切周每 30 秒复查，不累计故障。
- 读取失败保留旧金额并标记过期，不据此提醒或生成新趋势；完整父表校验成功而代理本周无数据时，显示“本周暂无数据”，不以零替代、不清除原档位。
- 详情区分整轮完整成功、最近数据更新、部分失败、分支补读、下次执行原因和逐代理更新时间；分支补读不计入整轮完整成功率。

### PC28 开奖触发

166 可启用盘口自身开奖触发，皇冠不受影响。

- 通过真实菜单进入即时注单，读取已开奖标题 `#drawLotterInfo #spanQishu`；加拿大2.0（JND282）支持已验证的开奖状态接口，加拿大网盘（JND28WEB）保留标题识别。
- 接口 `PreInstallments` 才是已开奖期号，`Installments` 是当前投注期，不能混用。
- 首次建立基准；确认新一期已开奖后等待 **15 秒**读取报表，同一期不重复触发。倒计时只安排下一次检测，检测间距为 5—60 秒，不直接触发报表。
- 来源不可用、期号倒退或持续停更时，退回设置的固定检查间隔；新期号恢复后重新按开奖触发。
- 若报表提供明确结算期号，则核对是否结算到目标期；落后时等待 30 秒复查。没有该字段时不能声称已确认结算，15 秒只是缓冲。

## 提醒规则

金额下方波线图可点击打开走势详情，支持最近30分钟、1小时、24小时；查看区间高低值、实际采样时间/金额及提醒标记关联记录。弹窗为打开/切换范围时的快照，不新增盘口请求；空档断开，不补造数据。此功能已随v1.0.42发布。

- 每个代理独立设置金额档位及备注，以 0 为基准；正负方向对称处理。
- 上升按固定档位边界提醒，回落有 **50% 档位缓冲**：每 10 万一档，12 万首次提醒10万档，20万提醒20万档，回落到19万不提醒，15万确认回到10万档；再次升至20万仍提醒。
- 同档不重复；低于首档保留最后非零档位，不因回到首档反复提醒。重启保留状态，换周重新判断。
- 修改金额间隔后按新间隔重新判断，仍遵守连续确认和静默策略；仅改备注或保存相同间隔不重置。
- 支持连续读取确认、连续失败升级、可选静默时间；静默默认关闭。静默期间未发送的新档位在结束后的下次有效读取判断补发。
- 另可设置单次变化阈值：首次有效读取建立基线，之后相邻有效读取的变化达到阈值才提醒。
- 普通金额消息显示本周金额、间隔、上一次档位、代理账号及括号备注，不显示报表区间、当前档位或单档“已进入此档位”。跨多档按规则逐档发送，超过20档合并说明。

## Telegram 与故障恢复

官方机器人为 [@runmingbot](https://t.me/runmingbot)。每台电脑配对一次；支持不同用户私聊配对，也支持群管理员发送 `/pair 配对码` 绑定群。群内查询和按钮仅管理员可用。

| 指令 | 功能 |
| --- | --- |
| `/status`、`/状态` | 当前监控状态，不触发报表读取 |
| `/report`、`/报表` | 请求在线电脑刷新并回传报表 |
| `/check 账号名` | 刷新指定账号 |
| `/top` | 当前金额排行，排除过期数据 |
| `/alerts` | 最近提醒 |
| `/help` | 帮助及查询按钮 |

查询结果区分新数据、部分完成及失败后保留的旧数据。电脑离线时无法执行新查询。

官方配对模式通过 Pages 入口与备用 Worker 转发，客户端不直接连接 Telegram API；只要中转可达，不必为 Telegram 单独开代理，但不保证所有大陆网络永久直连。盘口、通知和更新使用隔离的网络配置；高级手动 Bot Token 模式由本机访问 Telegram，受本地网络限制。

通知持久队列最多2000条，断线后逐条补发中间过程，不静默覆盖；更换收件人后旧队列暂存。客户端与中转按设备/通知编号去重；发送结果不确定时保留待确认，不能保证跨服务绝对零重复。账号完整失败达到设置次数才升级通知，恢复后通知一次；分支失败显示部分完成，不冒充整个账号掉线。

## 数据、安全与诊断

- 敏感配置通过系统加密服务保存；可导出同一系统账户使用的加密备份。安全码在配置界面明文显示，应注意屏幕和远程访问权限。
- 官方机器人 Token 保存在 Worker Secret，不打包到客户端；盘口登录资料不发给通知服务，通知正文会经中转送至 Telegram。
- 支持最近7天趋势、提醒记录、触发详情、发送回执及脱敏运行诊断；更新安装前保存运行诊断。
- 本机加密不能防止恶意软件读取正在使用的数据；不得把真实密码、令牌或原始登录请求写入仓库。
- 当前没有管理员审批激活/设备撤销机制；公开安装包不等于使用权限控制。

## 开发与验证

需要 Node.js 22+ 与 pnpm；当前 Windows CI 使用 Node.js 24。

```bash
pnpm install --frozen-lockfile
pnpm start
pnpm test
pnpm test:desktop
```

桌面测试使用隔离模拟环境，不能替代真实盘口或长期服务器验证。打包命令为 `pnpm build:win`、`pnpm build:mac`、`pnpm build:linux`，输出到 `dist`；当前已验证分发链是 Windows，其他平台不能仅凭构建配置声称已验收。

正式发布必须获得用户明确授权，依次完成本地测试、Windows 验证构建、标签发布、GitHub Release/R2 清单及完整安装包大小与 SHA-512 核对。具体入口和证据见 [维护上下文](MAINTENANCE_CONTEXT.md)；机器人服务部署见 [pairing-service/README.md](pairing-service/README.md)。
